Measured: memory ~ 0.20 x tolerance. The data's 1/3 Hubble time needs tolerance ~ 1.6 (links stretching
by ~165% before breaking); stored energy is then ~1.1 x the stiffness -> ~1e123 x too big.
A tolerance small enough for the size (3e-62) gives essentially zero memory.
Count excess: renewal theory says its change grows ~ lag/(12 x tolerance) (a random walk). Clear for tolerance 0.01
(1.1 -> 7.8 -> 14.1 vs expected 0.8 -> 4.2 -> 16.7); single runs are too noisy to show it for large tolerances. It is the
already-excluded 'bucket' (iteration 31).
Versus expectations: E1 was off -- memory is ~0.2 x tolerance, so ~1.6 (not 0.3-0.5) is needed, which makes E2 worse.
E3 held (random walk, clearest at small tolerance). E4 held (relative fluctuation 0.023 -> 0.009 for 10x more links).
Conclusion: link breaking explains WHY cells are added and gives sqrt(N) fluctuations automatically (N check above),
but it cannot give both the measured memory and the measured size. The memory must come from elsewhere (Hubble friction
of the jostled field, iteration 4); the size is not set by the tolerance.
